# 결정 기록

계획서(docs/PLAN.md)에서 정하지 않았거나 해석이 필요한 값과 그 근거. 모두 바꿀 수 있는 설정이다.

| 항목 | 정한 값 | 근거 | 바꿀 수 있는 곳 |
|---|---|---|---|
| 12V 시동 배터리 | 남은 시간·잔량을 **늘 "계산 불가"**. 차량이 보낸 경고 신호(모의)만 알람으로 알린다. 앱이 전압 기준을 따로 두지 않는다 | 전압 하나로는 온도·노후도·시동 부하를 알 수 없음(계획서 12.2). 임의 기준으로 "안전"처럼 보이면 안 됨 | `RuntimeEstimator.estimate` |
| 보호 종료 뒤 | 기상 타이머는 계속. 보호로 끈 장치는 복구 화면에서 **자동으로 다시 켜지 않음**("전력 보호로 종료됨") | 계획서 6절·12.4. 보존량에 닿은 전원으로 다시 켜면 보호 의미가 없음 | `RestorePlanner.plan(protectedTargets)` |
| 전력 알림의 '5분 더' | 소리만 미룸. 다시 알림 시각은 원래 기상 시각보다 늦어지지 않고, 보존량에 닿으면 미룬 중에도 장치를 끔 | 계획서 3절 7항 "미루기로 한도 연장 안 함" | `NapEngine.snooze` |
| 먼저 깨우는 시점 | 보호 기준 **10분 전**(초기 제안값). 처음부터 10분 안쪽이면 바로 | 계획서 12.4 | `ReserveSettings.warningLeadMinutes` |
| 보존량 기본값 | 전기차 SOC 30%(10~80% 조절), 캠핑 배터리 200Wh(50~1,000Wh) | 계획서 12.2·12.3 데모 예시. 제조사 보호 한계보다 낮출 권한이 있다는 뜻 아님 | `ReserveSettings`, `NapController.setReserve` |
| 측정값이 오래됨 | 60초 넘으면 "계산 불가" | 마지막 추정치를 지금 값처럼 유지하지 않기(12.3). 실차 주기는 확인 필요 | `RuntimeEstimator.STALE_MS` |
| 소비 0 / 충전 중 | 숫자 대신 "소비 없음" / "충전 중 — 분리 후 다시 계산" | 무한 시간·0으로 나누기 금지(N-T15) | `RuntimeEstimate.NoDrain/Charging` |
| 감시 중 측정값 끊김 | 한 번 안내, 상태 "계산 불가 · 알람만". 장치를 껐다고 처리하지 않음 | 계획서 12.4 마지막 문단 | `EnergyGuard.step` |
| 끌 장치 | 전기차 = 모의 공조, 캠핑 배터리 = 모의 캠핑 조명, 12V 만 있는 차 = 없음 | 차량 전체 전원·안전 장치·BMS 는 대상 아님. 캠핑 배터리에 순정 공조가 연결됐다고 가정하지 않음 | `VehicleProfile.shedLoads` |
| 화면의 보호 상태 | 내부 6단계를 "감시 중 / 곧 장치 종료 / 장치 종료됨 / 장치 종료 실패 — 직접 꺼 주세요 / 계산 불가 · 알람만"으로 묶어 표시 | 심사자·사용자가 한눈에 이해하도록 | `GuardStatus.simpleLabel` |
| 계산식 표시 | 남은 시간 옆에 `(남은 에너지 − 보존량) ÷ 소비 전력 = 시간`을 그대로 보여 줌 | 모의 입력이어도 계산은 실제임을 보이기 | `RuntimeEstimate.Available.formula` |
| 시연 시간 단축 | 장면 버튼은 보존량 근처로 값을 옮기고 배터리 소모를 30배속으로 돌림. 화면 문구에 "시간 단축"·"30배속" 표시 | 계획서 4절 마지막 문단(시간 단축을 숨기지 않기) | `NapController.sceneEv/sceneCamping/sceneStarter` |
| 하이브리드 등 | 선택지에 없음 | 검증 전 구동 배터리·엔진 동작을 추정하지 않음(12.1) | `VehicleProfile` |

## 2026-11-06 휴식 모드
- 하단에 캠핑, 영화관, 낮잠 버튼을 둔다. 모드별 실내등, 라디오, 시트 설정을 저장하고 버튼 하나로 적용한다. 켜진 모드를 다시 누르면 처음 값으로 되돌린다. 주차 상태에서만 쓴다.
- 낮잠 버튼은 휴식을 바로 시작한다. 시트는 기존 휴식 복구 흐름을 따르고, 실내등과 라디오는 휴식이 끝나면 되돌린다.
- 실내등은 Vehicle SDK 의 실내등 스위치만 쓴다. 전조등과 미등은 건드리지 않는다. 실제 기어 P 이고 차량이 끄기를 지원할 때만 실제 명령을 보낸다.
- 에뮬레이터는 실내등 명령에 성공을 답해도 값이 바뀌지 않는다. 그래서 값이 실제로 바뀐 경우에만 확인으로 표시한다.
- 공개 SDK 에서 시트 자세 제어(열선·통풍만 있음)와 라디오 선택 기능을 찾지 못해 둘은 모의로 두고 화면에 표시한다.
- 상단바의 남은 전력은 모의 전원 값이다. (2026-11-07 전기차는 실제 값으로 변경, 아래 참고)

## 2026-11-06 첫 화면과 실제 기어
- 첫 화면은 휴식 시간, 예상 알람 시각, 남은 사용 시간 한 줄, 휴식 시작만 보여 주고 차량·전원·공조·기록은 '설정'으로 접는다. 계산식은 설정과 휴식 화면에 남긴다.
- 시연 패널은 기본으로 닫는다. 앱을 켜면 실제 사용자 화면이 나온다.
- 기어는 Pleos Vehicle SDK 로 읽고 P 일 때만 주차로 본다. 값을 받지 못하거나 구독이 끊기면 상태 불명으로 보고 제어를 막는다. 시연 패널의 차량 상태는 모의 값이며 다음 실제 기어 값이 우선한다.
- 공조·시트·전원 제어는 모의 어댑터를 유지한다.

## 2026-11-07 전기차 실제 배터리 값
- 전기차 충전률과 용량은 Vehicle SDK `EvBattery` 로 읽는다. 권한은 `CAR_ENERGY`(충전률), `CAR_INFO`(용량)이고 둘 다 일반 권한이다.
- 소비 전력은 SDK 에 없어 모의 그대로다. 그래서 남은 시간은 "실제 잔량 ÷ 모의 소비 전력"이고 화면에 그렇게 표시한다.
- 시연 장면과 30배속은 값을 일부러 옮기므로 모의 값을 쓴다. 값을 못 읽는 차(내연기관차 포함)도 모의 값으로 돌아간다.
- 측정값 끊김·충전 중 토글은 실제 값을 쓸 때도 그대로 적용된다.
- 12V 시동 배터리는 공개 SDK 에 전압·잔량 API 가 없어 앱이 읽을 수 없다. "계산 불가" 유지.

## 2026-11-07 소비 전력 어림(공조·실내등 상태)
- SDK 에 소비 전력 값이 없어, 전기차는 차량에서 읽은 공조·실내등 상태로 소비 전력을 어림한다(`CabinLoad`). 권한 `CAR_CLIMATE`. 앱은 읽기만 하고 공조 명령은 보내지 않는다.
- 초기 제안값: 기본 200W, 송풍 최대 300W(단계 비례, 단계를 모르면 150W), 에어컨 1.2kW, 최대 냉방 1.8kW(에어컨 대신), 실내등 10W. 차종·외기 온도에 따라 크게 달라지는 어림값이라 화면에 "공조 상태로 추정"과 구성(예: 기본 200W + 송풍 4/8단 150W + 에어컨 1.2kW)을 그대로 보여 준다.
- 공조 전원을 못 읽으면 어림하지 않고 모의 소비 전력으로 돌아간다. 시연 장면·30배속도 모의 값을 쓴다.
- 전력 보호가 끄는 장치는 여전히 모의 공조다. 실제 공조는 끄지 않으므로, 보호 종료 뒤에도 실제 공조가 켜져 있으면 추정 소비는 그대로다.
- 에뮬레이터: 공조 전원 꺼짐, 에어컨 꺼짐, 바람 세기 3/8단, 실내등 꺼짐을 읽음. 바람 세기는 공조 전원과 지원 영역이 달라(앞줄 좌우만) 따로 구독한다. 최대 냉방은 미지원. 에뮬 공조 화면을 눌러도 값이 바뀌지 않아 상태 변화에 따른 화면 갱신은 미확인.
- 값 출처: 일반적인 전기차 공조 소비 범위를 바탕으로 정한 제안값이며 공식 측정치가 아니다.

## 2026-11-08 공조 켬은 시연 입력으로
- 에뮬에서 SDK 공조 값을 바꿀 방법이 없다: 에뮬 공조 패널·Extended Controls 모두 값이 안 바뀜(사용자 확인), `cmd car_service get/set-property-value`·`inject-vhal-event` 는 user 빌드라 거부, 에뮬 콘솔에 차량 데이터 명령 없음.
- 그래서 시연 패널에 '공조 켬(시연 입력 · 에어컨 포함)' 스위치를 둔다. 켜면 실제 공조 상태 대신 공조 전원 켬 + 에어컨 켬으로 어림한다(실제 바람 세기는 그대로). 기본은 꺼짐이고 시연 패널 안에만 있어 사용자 화면에는 영향이 없다.
- 에뮬 확인: 끔 200W → 270시간 54분, 켬 1.5kW(기본 200W + 송풍 3/8단 113W + 에어컨 1.2kW) → 35시간 49분, 다시 끄면 270시간 54분. 실제 공조 변화에 따른 갱신은 실차 확인으로 남긴다.

## 2026-11-07 메인 화면 정리
- 메인 화면은 상단바(남은 전력 게이지, 남은 시간 큰 글씨, 설정)와 하단 버튼(캠핑·영화관·낮잠 시작)만 둔다. 주차가 아닐 때 경고, 버튼을 누른 뒤 결과 문구는 그때만 나온다.
- 휴식 시간 고치기(15·30·60분, −5·+5)는 '낮잠 시작' 뒤 휴식 화면으로 옮겼다. 낮잠 시작은 지난번 시간으로 바로 시작하고, 휴식 화면에서 전체 시간을 바꾸면 시작 시각 기준으로 목표 시각을 다시 저장한다(`NapEngine.setDuration`). 남은 시간이 1분 미만이 되는 변경, 다시 알림 대기, 시연 단축 중에는 바꾸지 않는다.
- 메인 화면의 말하기 버튼은 뺐다. 음성은 휴식 화면의 말하기로 쓴다. '기상 보장 아님' 안내는 설정 안으로 옮겼다.

## 2026-11-11 메인 화면: 휴대폰식 상단바 + 하단 모드 탭 바
- 사용자 결정: 메인 화면 위는 휴대폰 상단바처럼 얇은 한 줄(왼쪽 시계·지금 모드, 오른쪽 남은 시간·배터리 아이콘·%·설정), 아래는 휴대폰 탭처럼 아이콘이 있는 모드 바(캠핑·영화관·낮잠).
- 탭을 누르면 그 모드 설정을 바로 적용하고, 다른 탭을 누르면 그 모드로 바뀌며, 켜진 탭을 다시 누르면 원래대로 되돌린다(ModeRules 그대로). 낮잠 탭은 바로 휴식 타이머를 시작한다.
- 가운데는 켜진 모드(적용 결과·'모드 끄고 원래대로')를 크게, 꺼져 있으면 모드마다 무엇을 바꾸는지 안내한다. 11-07의 48sp 남은 시간은 상단바 한 줄로 옮겼다.
- 배터리 아이콘 안 흰 세로선은 보존량, 보존량+10% 이하면 빨강. 12V 만 있는 차는 빈 아이콘과 '계산 불가'.
- (같은 날 추가) 상단바 배터리 아이콘 옆 큰 글씨는 남은 시간, 그 옆 작게 '100% · 220W 사용 중'. 공조(시연 입력)·라디오(모드가 켬, 모의 20W)·실내등(10W)을 켜고 끄면 소비 전력과 남은 시간이 바로 바뀐다. 에뮬 확인: 기본 200W 270시간 54분 → 영화관(라디오) 220W 246시간 16분 → 공조 켬 1.5kW 35시간 21분. 라디오 20W 는 보통 음량 차량 오디오의 초기 제안값(차종에 따라 다름).

## 2026-11-11 하단바 ＋ 로 모드 추가
- 사용자 결정: 하단바 맨 끝 ＋(모드 추가)로 모드를 더 만들고, 추가할 때마다 탭 칸이 같은 비율로 좁아진다(모든 칸 weight 1).
- 추가 창: 이름(8글자까지)·아이콘 8개 중 하나·실내등 끄기·라디오 켜기(모의)·시트 자세(모의). 추가한 모드는 낮잠처럼 타이머를 켜지 않고 설정만 적용한다. 누르기·다시 눌러 원래대로·다른 모드로 바꿀 때 처음 값 유지는 기본 모드와 같은 규칙(ModeRules.pressCustom).
- 제한: 추가는 5개까지(탭 최대 9칸, 그 뒤 ＋ 칸은 사라짐), 빈 이름·같은 이름 거절. 칸이 6개 이상이면 글자 크기를 줄이고 긴 이름은 줄임표.
- 지우기는 ⚙ 설정의 모드 카드 '모드 지우기'. 켜져 있는 모드는 끈 뒤에 지울 수 있다(처음 값 복원 경로를 잃지 않게).
- 저장: RestPreferences.customModes, ActiveMode.customId(예전 저장 파일은 기본값으로 읽힘). 에뮬에서 추가·켜기(라디오로 270h54→246h16)·끄기·지우기 확인.

## 2026-11-12 메인 = 가운데 초록 배터리 원 + 오른쪽 위 남은 시간 + 하단바·옆 창
- 사용자: "메인 화면이 너무 심심하다" → 링·모드 카드 시안을 거쳐, 사용자 지시로 최종 구성을 정했다: "가운데 초록 원 배터리 바, 오른쪽 위 남은 시간, 나머지는 비우고, 하단바를 누르면 전체가 왼쪽으로 밀리고 누른 버튼의 창이 나오게".
