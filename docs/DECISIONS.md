# 결정 기록

계획서(docs/PLAN.md)에서 정하지 않았거나 해석이 필요한 값과 그 근거. 모두 바꿀 수 있는 설정이다.

| 항목 | 정한 값 | 근거 | 바꿀 수 있는 곳 |
|---|---|---|---|
| 12V 시동 배터리 | 남은 시간·잔량을 **늘 "계산 불가"**. 차량이 보낸 경고 신호(모의)만 알람으로 알린다. 앱이 전압 기준을 따로 두지 않는다 | 전압 하나로는 온도·노후도·시동 부하를 알 수 없음(계획서 12.2). 임의 기준으로 "안전"처럼 보이면 안 됨 | `RuntimeEstimator.estimate` |
| 보호 종료 뒤 | 기상 타이머는 계속. 보호로 끈 장치는 복구 화면에서 **자동으로 다시 켜지 않음**("전력 보호로 종료됨") | 계획서 6절·12.4. 보존량에 닿은 전원으로 다시 켜면 보호 의미가 없음 | `RestorePlanner.plan(protectedTargets)` |
| 전력 알림의 '5분 더' | 소리만 미룸. 다시 알림 시각은 원래 기상 시각보다 늦어지지 않고, 보존량에 닿으면 미룬 중에도 장치를 끔 | 계획서 3절 7항 "미루기로 한도 연장 안 함" | `NapEngine.snooze` |
| 먼저 깨우는 시점 | 보호 기준 **10분 전**(초기 제안값). 처음부터 10분 안쪽이면 바로 | 계획서 12.4 | `ReserveSettings.warningLeadMinutes` |
| 보존량 기본값 | 전기차 SOC 30%(10~80% 조절), 캠핑 배터리 200Wh(50~1,000Wh) | 계획서 12.2·12.3 데모 예시. 제조사 보호 한계보다 낮출 권한이 있다는 뜻 아님 | `ReserveSettings`, `NapController.setReserve` |
| 측정값이 오래됨 | 60초 넘으면 "계산 불가" | 마지막 추정치를 지금 값처럼 유지하지 않기(12.3). 실차 주기는 확인 필요 | `RuntimeEstimator.STALE_MS` |
| 소비 0 / 충전 중 | 숫자 대신 "소비 없음" / "충전 중 — 분리 후 다시 계산" | 무한 시간·0으로 나누기 금지(N-T15) | `RuntimeEstimate.NoDrain/Charging` |
| 감시 중 측정값 끊김 | 한 번 안내, 상태 "계산 불가 · 알람만". 장치를 껐다고 처리하지 않음 | 계획서 12.4 마지막 문단 | `EnergyGuard.step` |
| 끌 장치 | 전기차 = 모의 공조, 캠핑 배터리 = 모의 캠핑 조명, 12V 만 있는 차 = 없음 | 차량 전체 전원·안전 장치·BMS 는 대상 아님. 캠핑 배터리에 순정 공조가 연결됐다고 가정하지 않음 | `VehicleProfile.shedLoads` |
| 화면의 보호 상태 | 내부 6단계를 "감시 중 / 곧 장치 종료 / 장치 종료됨 / 장치 종료 실패 — 직접 꺼 주세요 / 계산 불가 · 알람만"으로 묶어 표시 | 심사자·사용자가 한눈에 이해하도록 | `GuardStatus.simpleLabel` |
| 계산식 표시 | 남은 시간 옆에 `(남은 에너지 − 보존량) ÷ 소비 전력 = 시간`을 그대로 보여 줌 | 모의 입력이어도 계산은 실제임을 보이기 | `RuntimeEstimate.Available.formula` |
| 시연 시간 단축 | 장면 버튼은 보존량 근처로 값을 옮기고 배터리 소모를 30배속으로 돌림. 화면 문구에 "시간 단축"·"30배속" 표시 | 계획서 4절 마지막 문단(시간 단축을 숨기지 않기) | `NapController.sceneEv/sceneCamping/sceneStarter` |
| 하이브리드 등 | 선택지에 없음 | 검증 전 구동 배터리·엔진 동작을 추정하지 않음(12.1) | `VehicleProfile` |
