# 3번 앱 개발 계획서 — 낮잠·차박 알람 및 전력 관리
작성: 2026-10-31 · 수정: 2026-11-02 · 내부 제출 목표: 2026-11-04
변경: 전기차·내연기관차를 하나의 앱으로 지원하고, 낮잠 알람에 잔여 사용 시간 예측·전력 보호 기능을 통합한다. 파일명은 기존 참조 호환을 위해 유지한다.
상태: 개발 지시용 계획. 차량 원격 시동·경적 제어는 구현 확정 사항이 아니다.

## 1. 만들 경험
주차한 전기차 또는 내연기관차에서 쉬려는 사람이 기상 시각과 남겨 둘 에너지를 설정한다. 앱은 낮잠·차박 시간을 관리하고, 연결된 전원 정보가 충분하면 전기 장치를 얼마나 더 사용할 수 있는지 추정한다. 기상 시각 또는 전력 보호 기준에 맞춰 알리고, 지원되는 편의 장치의 종료를 요청한다.

차량 종류만으로 기능을 결정하지 않는다. 전기차 구동 배터리, 내연기관차 12V 시동 배터리, 별도 캠핑 배터리를 서로 다른 전원으로 관리한다. 모든 사용자에게 알람을 제공하며, 전력 예측·자동 제어는 확인된 데이터·장치·권한에 따라 제공한다. 전기차 전용 앱으로 축소하지 않는다.

시제품은 실제 카운트다운, 앱 내부 알람 소리·음성, 다시 알림, 종료, 기록과 전력 예측·보호 상태 판단 로직을 구현한다. 배터리·소비전력 입력과 공조·시트·장치 종료는 모의 연동으로 보여준다. 원격 시동·엔진 정지·경적·차량 전체 전원 차단은 P0에서 실행하지 않는다. 기존의 휴대폰 사전 예약·시트 복귀 아이디어는 유지한다.

## 2. 구현 범위
| 기능 | P0 | P1/확장 |
|---|---|---|
| 낮잠 시간 설정 | 터치 + 가능하면 음성, 예상 기상 시각 | 개인별 일정·반복 예약 |
| 실제 타이머 | 앱 실행 중 실제 시간으로 동작 | OS 절전·백그라운드 동작 검증 |
| 차량·전원 유형 | 전기차/내연기관차 및 전원 출처 선택 | 검증된 차량·외부 배터리 자동 인식 |
| 남은 사용 시간 | 가상 전원 입력으로 실제 계산·갱신 | 차종별 실측 보정·신뢰도 평가 |
| 에너지 보호 목표 | 구동/캠핑 배터리 잔량 목표, 시동 배터리는 별도 보호 정책 | 다음 충전소까지의 에너지 예약 |
| 종료 전 기상 알림 | 보호 기준 접근 시 별도 알람 | 실차·앱 수명 검증 |
| 장치 종료 | 사전 선택한 모의 편의 장치에 종료 요청·결과 확인 | 지원 장치별 실제 제어 |
| 데이터 부족 처리 | 예상 시간 표시 안 함·알람만 사용 | 추가 센서/BMS 연결 |
| 깨우기 | 앱 내부 소리·TTS·확인 버튼 | 허용되는 추가 알림 채널 |
| 다시 알림 | 기본 5분은 개발 제안값 | 사용자 설정 |
| 공조 온도 | 모의 요청·성공/실패 피드백 | 지원 차종·권한 확인 후 실제 API |
| 시트 휴식 자세 | 모의 이동·복귀 확인 | 지원 API·안전 조건 확인 후 연결 |
| 원래 설정 복구 | 저장된 모의 설정을 확인 후 복구 | 실제 상태 비교·부분 복구 |
| 휴대폰에서 10분 전 준비 | 시연 패널에서 예약 이벤트 주입 | 모바일 앱·서버·원격 제어 제휴 |
| 잠금 해제 시 준비 | 모의 이벤트 선택 기능, P1 | 권한·사용자 동의·기동 조건 검토 |
| 경적·엔진 시동 | P0에서는 실행하지 않음 | 제조사 허용 범위와 운영 조건 검토 |
| 충전 상태 연계 | P1: 상태 표시·종료 제안 | 실제 충전 이벤트 검증 |

전기차와 내연기관차는 같은 화면 흐름을 사용하되 전원 모델과 지원 기능은 다르게 적용한다. 엔진이 꺼진 일반 내연기관차에서 순정 냉난방이 전기차처럼 지속 작동한다고 가정하지 않는다. 캠핑 배터리도 연결만으로 순정 공조를 구동하는 것이 아니며, 실제 연결된 별도 전기 장치만 관리한다. 차량 전체 전원이나 BMS 보호 기능을 앱이 제어한다고 표현하지 않는다. 상세 분기와 계산은 12절을 따른다.

## 3. 사용자 흐름
1. 주차 여부, 차량 유형, 전원 출처와 앱 알람의 동작 범위를 표시한다.
2. 낮잠 모드(시간 길이) 또는 차박 모드(기상 시각)를 선택한다. 낮잠 15분/30분/60분은 초기 프리셋 제안이다.
3. 전원별 보호 목표와 허용된 종료 대상 장치를 정한다. 예상 기상 시각, 모의 온도·시트 설정, 전력 사용 가능 시간을 비교한다. 데이터가 부족하면 추정 시간을 만들지 않는다.
4. '휴식 시작'으로 타이머를 시작하고 현재 설정을 저장한다.
5. 준비 동작이 실패하면 실패를 안내한다. 사용자가 타이머만 계속할 수 있게 한다.
6. 기상 시간이 되면 앱 내부 알람과 '설정한 휴식 시간이 끝났습니다' 안내를 재생한다. 전력 보호 기준이 먼저 가까워지면 그전에 별도 기상 알림을 제공한다.
7. '일어났어/종료' 또는 '5분 더'를 받는다. 전력 보호 알림을 미루더라도 보호 기준이나 종료 시각은 연장하지 않는다. 정해 둔 전력 한도에 도달하면 사전 설정한 모의 종료 동작을 수행하고 결과를 표시한다.
8. 깨어난 사용자가 확인한 뒤 원래 설정 복귀를 요청한다. 시트 자동 복귀는 P0에서 모의 동작만 한다.
9. 실제 휴식 시간·종료 사유를 저장한다. 수면 시간이나 수면의 질을 측정한 것처럼 표시하지 않는다.

'30분'과 '3분'처럼 혼동하기 쉬운 음성 입력은 '30분 뒤, 오후 2시 30분에 알려드릴까요?'처럼 재확인한다. 낮잠 입력은 1~180분, 차박은 날짜가 포함된 기상 시각으로 다음 24시간 이내를 초기 제안 범위로 둔다. 두 범위는 설정으로 분리하고 장시간 알람의 실제 동작은 별도로 검증한다.

## 4. 타이머와 프로세스 수명
### 실행 중
- 화면의 숫자를 1초씩 빼는 값을 진실의 원천으로 사용하지 않는다.
- Clock 인터페이스에서 경과 시간과 목표 시각을 계산한다.
- 실행 중 경과 시간은 단조 시계를 우선 사용해 시스템 시각 변경의 영향을 줄인다.
- 화면 재구성·회전으로 타이머를 새로 시작하지 않는다.
- 알람 이벤트는 sessionId + alarmType + sequence별로 한 번만 발행한다. 다시 알림과 전력 보호 알림은 별도 순번을 사용하되 같은 이벤트를 중복 재생하지 않는다.

### 종료·복원
- 시작 시각, 목표 기상 시각, 세션 상태, 다시 알림 횟수를 영속 저장한다.
- 프로세스가 종료된 뒤 재실행하면 저장된 목표 시각과 현재 시각을 비교한다.
- 기상 시각이 지났다면 '예정된 알람 시각이 지났습니다'를 표시한다. 꺼진 동안 울리지 않았는데 정상 기상 알림을 수행했다고 기록하지 않는다.
- 아직 시간이 남으면 남은 시간을 보여주고 복원한다. 시각이 크게 바뀌었거나 기기가 재부팅된 경우 사용자에게 일정을 재확인한다.
- 사용자가 Android 설정에서 앱을 강제 중지한 경우까지 알람을 보장하지 않는다.

이번 P0는 앱이 실행되고 차량 시스템이 깨어 있는 환경에서 검증한다. 전원 OFF/슬립/백그라운드 동작은 별도 검증 전 '지원 확인 필요'다. 출시 기능에서는 앱 수명·정확한 알람 권한·오디오·차량 전원 정책을 함께 검토해야 한다. WorkManager를 정확한 기상 타이머로 대신 쓰지 않는다.

시연 시간을 줄이려면 '데모 20초' 또는 가상 시계 이동 기능을 제공한다. 영상에 시간 단축 시연임을 표시하고 30분 동안 실제 대기한 것처럼 설명하지 않는다.

## 5. 상태 전이
~~~mermaid
stateDiagram-v2
    [*] --> Setup
    Setup --> Preparing: 시간·설정 확인
    Preparing --> Resting: 준비 완료 또는 타이머만 시작
    Preparing --> Setup: 취소
    Resting --> Ringing: 목표 시각
    Ringing --> Snoozed: 다시 알림
    Snoozed --> Ringing: 연장 시각
    Ringing --> RestorePending: 기상 확인
    Resting --> RestorePending: 중도 종료
    RestorePending --> Finished: 복구 확인 또는 건너뛰기
    Finished --> Setup
~~~
실제 차량이 움직이거나 상태가 불명확해지면 차량 제어 요청을 막고, 플랫폼 제한에 맞게 휴식 흐름을 중지/축소한다. UI가 백그라운드로 갔다고 시트 복귀를 실행하지 않는다.

위 휴식 세션 상태와 별도로 EnergyGuard 상태를 관리한다: UNAVAILABLE / MONITORING / WARNING / SHED_REQUESTED / SHED_CONFIRMED / SHED_FAILED. 기상 알람이 꺼졌다고 전력 보호 상태가 초기화되면 안 된다. 보호 종료 뒤에는 원래 공조 설정을 자동 재적용하지 않는다.

## 6. 차량 제어 어댑터
우리가 정의하는 인터페이스:
- VehicleCapabilityProvider: 기능·권한·전원·차량 상태 확인.
- ClimateController: 현재 설정 조회, 요청, 응답.
- SeatController: 지원되는 자세 조회, 요청, 응답.
- AlarmOutput: 앱 소리/TTS 시작·중지.
- NapRepository: 세션·설정·기록 저장.
- Clock: 실제/테스트/시연용 시계.
- EnergySourceAdapter: 전원별 잔여 에너지·소비전력·출처·측정 시각 제공.
- RuntimeEstimator: 전원에 맞는 잔여 사용 시간 추정 또는 UNKNOWN 반환.
- EnergyGuard: 보호 목표·알림 시각·장치 종료 조건 판단.
- AccessoryLoadController: 지원되는 개별 편의 장치의 종료 요청·실제 상태 확인. 차량 전체 전원 차단 API가 아니다.

공식 Vehicle SDK 소개에는 공조·좌석 관련 기능이 설명돼 있다. 실제 setter, 권한, 지원 차종과 좌석, 동작 가능한 전원 상태를 확인한 뒤 Pleos 어댑터를 구현한다. 사용자 제공 목록의 'Vehicle Control 준비 중'과 문서의 제어 소개가 일치하지 않을 수 있으므로, 권한이 있다고 추정하지 말고 SDK_VERIFICATION에 실제 결과를 기록한다.

### 제어 요청 상태
REQUESTED → ACKNOWLEDGED/FAILED/TIMED_OUT.
화면에서 버튼을 눌렀다는 이유만으로 '온도 설정 완료/시트 이동 완료'라고 표시하지 않는다. ACKNOWLEDGED도 요청 접수인지 물리적 적용 확인인지 어댑터 계약에 명시한다.

### 복구 규칙
- 시작 전에 읽은 유효한 원래 값만 저장한다.
- 앱이 변경한 항목만 복구 후보로 삼는다.
- 휴식 중 사용자가 수동으로 바꾼 항목은 덮어쓰지 않고 확인한다.
- 좌석 움직임은 사용자 확인·정차 조건·지원 여부를 충족해야 한다.
- 일부 항목만 성공하면 항목별 성공/실패를 보여준다. 공조 실패를 시트 성공으로 가리지 않는다.
- 전력 보호로 종료된 세션에서는 공조·부하를 자동으로 다시 켜지 않는다. 필요하면 충분한 전원 상태와 사용자 확인을 거쳐 새로 시작한다.
- demoRelease에서는 실제 제어 구현을 호출하지 않는다.

## 8. 화면·음성·알람
1. 시작: 전기차/내연기관차, 실제 전원 출처, 낮잠/차박 모드, 기상 예정 시각.
2. 휴식 설정: 모의 온도·좌석, 적용 상태.
3. 휴식 중: 어두운 화면, 기상까지 남은 시간과 장치 사용 가능 예상 시간을 구분, 보호 목표, 종료 버튼.
4. 알람: 기상 확인·다시 알림, 음성 명령.
5. 복구: 복구 항목 확인, 성공/실패, 건너뛰기.
6. 기록: 계획한 시간과 실제 앱 세션 시간.
7. 시연 패널: 20초 타이머·모의 예약·제어 실패·전기차/내연기관차/캠핑 배터리 상태·소비량 변화·데이터 단절.

알람은 갑자기 과도한 음량이 되지 않도록 앱의 허용 범위에서 조절하고 즉시 중지할 수 있게 한다. 호출·음성 안내와 오디오 포커스가 충돌한 상황을 테스트한다. 공조가 있다는 이유로 밀폐 공간의 내연기관 시동을 안전하다고 판단하지 않는다. 이 앱은 차량 내 체류 안전이나 기상을 보장하는 장치가 아니다.

## 12. 전기차·내연기관차 통합 전력 관리 상세
### 12.1 지원 방식
앱은 하나이며 전원 출처와 기능 지원 여부에 따라 메뉴를 구성한다. 자동으로 확인하지 못한 차량 종류는 사용자가 고르게 하되, 사용자가 선택했다는 이유만으로 실제 제어 권한이 생기지는 않는다.

| 차량·전원 | 공통 기능 | 잔여 시간 추정 | 제어 범위 |
|---|---|---|---|
| 전기차 구동 배터리 | 기상·휴식 기록·전력 안내 | 지원되는 잔여 에너지와 총 소비량으로 계산 | 허용된 공조·편의 장치 |
| 내연기관차 순정 12V 시동 배터리 | 기상·지원되는 상태 경고 | 검증된 배터리 모델·전류·상태 정보가 있을 때만; 전압 하나로 계산 금지 | 지원되는 편의 장치만, 엔진 시동/정지는 P0 제외 |
| 전기차/내연기관차 별도 캠핑 배터리 | 기상·전력 사용 관리 | 해당 배터리/BMS 정보 또는 명시된 모의 데이터 | 실제 그 전원에 연결되고 제어 인터페이스가 있는 장치 |
| 전원 데이터 없음 | 낮잠·차박 알람 | '잔여 사용 시간 계산 불가' | 수동 안내만, 모의 제어와 구분 |
| 하이브리드 등 미검증 구성 | 공통 알람 | 검증 전 제한 | 구동 배터리/엔진 동작을 추정해 제어하지 않음 |

내연기관차도 전체 앱의 지원 대상이다. 다만 엔진 OFF 상태에서 순정 에어컨·히터를 전기로 계속 가동하는 기능을 모든 차에 약속하지 않는다. 캠핑 배터리를 설치했다는 사실만으로 순정 공조가 연결됐다고 간주하지 않는다.

### 12.2 남겨 둘 에너지
구동·캠핑 배터리의 보호 목표는 '바닥까지 쓰기'가 아니라 사용자가 남기려는 에너지다. 예: 고전압 배터리 30% 보존. 이 값은 예시이며 제조사 기준·차량 보호 한계보다 낮출 수 있는 권한이 있다는 뜻이 아니다.

전기차 확장안:
예약 에너지 = max(사용자 보존량, 다음 충전소까지 예상 소모량 + 여유분, 제조사가 제공한 해당 기능의 하한).
각 값은 같은 사용 가능 에너지 기준으로 환산할 수 있을 때만 비교한다. 경로·소모 모델이 없으면 충전소 도착을 보장하지 않고 사용자 보존량만 사용한다.

12V 시동 배터리는 임의의 20%/30%를 남긴다고 재시동이 보장되지 않는다. 전압·온도·노후도·시동 부하 등 조건과 검증된 제조사/장치 보호 정책이 필요하다. 충분한 데이터가 없으면 퍼센트 기반 자동 차단·확정 잔여 시간을 제공하지 않고 상태 안내와 알람을 유지한다.

### 12.3 계산
기본 식(단위: Wh, W, 시간):
남은 사용 시간 = max(현재 사용 가능 에너지 - 예약 에너지, 0) / 최근의 보수적인 총 방전 전력.

- 총 방전량에는 공조뿐 아니라 조명·전장품·전원 변환 손실 등 같은 전원에서 나가는 소비를 포함한다. 합산할 때 이미 포함된 부하를 중복 계산하지 않는다.
- 사용 가능 에너지가 직접 제공되면 우선 사용한다. 용량×SOC는 용량 정의와 SOC 기준이 일치할 때의 근사다.
- 정격 용량이나 차량 광고상의 배터리 용량을 실제 남은 사용 가능 에너지로 간주하지 않는다.
- 최근 평균을 평활화하고 급격한 소비 증가를 반영한다. 데이터가 충분히 쌓이기 전에는 '계산 중'을 표시한다.
- 입력이 오래됐거나 결측이면 '계산 불가'로 바꾼다. 마지막 추정치를 현재 값처럼 유지하지 않는다.
- 충전·발전이 들어와 순방전이 0 이하이면 무한 시간을 표시하지 않는다. '충전/전원 공급 중 — 분리 후 재계산'을 표시한다.
- 전압만 있는 12V 배터리에 이 식을 적용하기 위해 임의 잔량을 만들어내지 않는다.
- 차박 중 변화가 큰 조건에서는 단일 시각을 보장하지 않고 '현재 소비 기준 예상'이라고 표시한다.

데모 계산 예:
전기차에 실제 사용 가능 총용량 60kWh라는 가정을 주고, 현재 SOC 60%, 예약 SOC 30%, 총 소비 1.5kW로 입력하면 (36-18)/1.5 = 12시간. 소비가 3kW로 증가하면 6시간이다. 모두 가상 입력이며 차종 실측 결과가 아니다.

별도 캠핑 배터리 데모:
현재 사용 가능 800Wh, 예약 200Wh, 모의 조명 등 총 부하 100W이면 6시간. 이는 별도 배터리에 연결된 장치의 예시이며 내연기관차 순정 에어컨 사용 시간을 뜻하지 않는다.

### 12.4 알림과 자동 종료
설정: 기상 시간, 보호 목표, 종료 대상 부하, 사전 알림 시점, 허용된 자동 종료를 세션 시작 전에 확인한다.

1. 휴식 중 배터리와 기상 시간을 함께 모니터링한다.
2. 예상 보호 시점이 기상보다 빠르면 즉시 안내한다.
3. 보호 시점 가까이에는 별도 기상 알림을 제공한다. 10분 전은 초기 제안값이며 급격한 소비 변화에는 더 일찍 또는 즉시 알릴 수 있다.
4. 보호 기준에 도달하면 사전에 선택한 지원 부하에 종료를 요청한다. 사람의 응답이 없다고 무기한 전력을 계속 소비하는 정책으로 만들지 않는다.
5. 실제 상태 응답으로 종료 여부를 확인한다. 실패·미지원이면 사용자가 직접 조치하도록 별도 알린다.
6. 차량의 자체 보호 기능을 우회하지 않는다. 앱 종료 후에도 보호가 지속되려면 차량/장치 쪽 독립 보호가 필요하다.

잠든 사람의 냉난방을 조용히 끊는 것을 안전 기능으로 표현하지 않는다. 사전 기상 알림, 온도·상태 경고, 사용자가 설정한 종료 범위를 함께 제공한다. 차량 전체 전원·안전 장치·도어 잠금·주차 브레이크·BMS를 종료 대상으로 삼지 않는다. 앱 알람이 작동할 최소 전원도 항상 남는다고 보장하지 않는다.

급격한 배터리 저하나 데이터 단절 때문에 사전 알림 여유가 없어지면 즉시 상태를 알린다. 현재 데이터가 없는데 안전한 종료가 완료됐다고 처리하지 않는다. 실차 자동 제어는 해당 제조사/장치의 지원 조건을 검증한 뒤 단계적으로 연결한다.

### 12.5 1차 시제품의 완료 범위
- 두 차량 유형을 선택하고 낮잠·차박 알람을 실제로 동작시킨다.
- 전기차·캠핑 배터리의 가상 입력에 따라 예상 시간을 실제 계산한다.
- 12V 시동 배터리 데이터가 부족한 상황을 '계산 불가'로 정확히 보여준다.
- 소비량 상승 → 남은 시간 감소 → 기상 알림 → 모의 장치 종료/실패를 시연한다.
- 모든 모의 입력·제어를 화면과 영상에서 표시한다.
- 외부 서버 배포는 이 P0에 필요하지 않다. 가상 데이터·설정·기록은 로컬로 처리한다.
- 실제 차량의 장시간 전력 공급·슬립 중 실행·공조 제어·재시동 보호는 검증 전 미확인으로 유지한다.
