# 3번 앱 개발 계획서 — 낮잠 알람
작성: 2026-10-31 · 내부 제출 목표: 2026-11-04
상태: 개발 지시용 계획. 차량 원격 시동·경적 제어는 구현 확정 사항이 아니다.

## 1. 만들 경험
주차한 차에서 잠깐 쉬려는 사람이 쉬는 시간을 정하고, 원하는 휴식 설정을 적용한 뒤, 시간이 되면 안내를 받고 차를 다시 사용할 준비를 한다.

시제품은 실제 카운트다운, 앱 내부 알람 소리·음성, 다시 알림, 종료, 기록을 구현한다. 공조·시트·휴대폰 사전 예약은 모의 연동으로 경험을 보여준다. 차량 경적과 원격 시동은 제조사 협력·권한 검토가 필요한 후속 기능으로 남긴다.

## 2. 구현 범위
| 기능 | P0 | P1/확장 |
|---|---|---|
| 낮잠 시간 설정 | 터치 + 가능하면 음성, 예상 기상 시각 | 개인별 일정·반복 예약 |
| 실제 타이머 | 앱 실행 중 실제 시간으로 동작 | OS 절전·백그라운드 동작 검증 |
| 깨우기 | 앱 내부 소리·TTS·확인 버튼 | 허용되는 추가 알림 채널 |
| 다시 알림 | 기본 5분은 개발 제안값 | 사용자 설정 |
| 공조 온도 | 모의 요청·성공/실패 피드백 | 지원 차종·권한 확인 후 실제 API |
| 시트 휴식 자세 | 모의 이동·복귀 확인 | 지원 API·안전 조건 확인 후 연결 |
| 원래 설정 복구 | 저장된 모의 설정을 확인 후 복구 | 실제 상태 비교·부분 복구 |
| 휴대폰에서 10분 전 준비 | 시연 패널에서 예약 이벤트 주입 | 모바일 앱·서버·원격 제어 제휴 |
| 잠금 해제 시 준비 | 모의 이벤트 선택 기능, P1 | 권한·사용자 동의·기동 조건 검토 |
| 경적·엔진 시동 | P0에서는 실행하지 않음 | 제조사 허용 범위와 운영 조건 검토 |
| 충전 상태 연계 | P1: 상태 표시·종료 제안 | 실제 충전 이벤트 검증 |

전기차와 내연기관을 하나의 공조 제어 방식으로 가정하지 않는다. 내연기관의 공조 유지에 시동이 필요한 경우도 있으므로 기능 지원·전원 조건을 확인한다. 앱이 엔진이나 공조를 항상 켤 수 있다는 표현은 사용하지 않는다.

## 3. 사용자 흐름
1. 주차 여부와 앱 알람의 동작 범위를 표시한다.
2. 15분/30분/60분 또는 직접 입력으로 시간을 정한다. 이는 초기 프리셋 제안이다.
3. 예상 기상 시각, 모의 온도·시트 설정을 확인한다.
4. '휴식 시작'으로 타이머를 시작하고 현재 설정을 저장한다.
5. 준비 동작이 실패하면 실패를 안내한다. 사용자가 타이머만 계속할 수 있게 한다.
6. 시간이 되면 앱 내부 알람과 '설정한 휴식 시간이 끝났습니다' 안내를 재생한다.
7. '일어났어/종료' 또는 '5분 더'를 받는다.
8. 깨어난 사용자가 확인한 뒤 원래 설정 복귀를 요청한다. 시트 자동 복귀는 P0에서 모의 동작만 한다.
9. 실제 휴식 시간·종료 사유를 저장한다. 수면 시간이나 수면의 질을 측정한 것처럼 표시하지 않는다.

'30분'과 '3분'처럼 혼동하기 쉬운 음성 입력은 '30분 뒤, 오후 2시 30분에 알려드릴까요?'처럼 재확인한다. P0 권장 입력 범위는 1~180분이며 문서·설정에서 변경 가능하게 한다.

## 4. 타이머와 프로세스 수명
### 실행 중
- 화면의 숫자를 1초씩 빼는 값을 진실의 원천으로 사용하지 않는다.
- Clock 인터페이스에서 경과 시간과 목표 시각을 계산한다.
- 실행 중 경과 시간은 단조 시계를 우선 사용해 시스템 시각 변경의 영향을 줄인다.
- 화면 재구성·회전으로 타이머를 새로 시작하지 않는다.
- 알람 이벤트는 sessionId별로 한 번만 발행한다.

### 종료·복원
- 시작 시각, 목표 기상 시각, 세션 상태, 다시 알림 횟수를 영속 저장한다.
- 프로세스가 종료된 뒤 재실행하면 저장된 목표 시각과 현재 시각을 비교한다.
- 기상 시각이 지났다면 '예정된 알람 시각이 지났습니다'를 표시한다. 꺼진 동안 울리지 않았는데 정상 기상 알림을 수행했다고 기록하지 않는다.
- 아직 시간이 남으면 남은 시간을 보여주고 복원한다. 시각이 크게 바뀌었거나 기기가 재부팅된 경우 사용자에게 일정을 재확인한다.
- 사용자가 Android 설정에서 앱을 강제 중지한 경우까지 알람을 보장하지 않는다.

이번 P0는 앱이 실행되고 차량 시스템이 깨어 있는 환경에서 검증한다. 전원 OFF/슬립/백그라운드 동작은 별도 검증 전 '지원 확인 필요'다. 출시 기능에서는 앱 수명·정확한 알람 권한·오디오·차량 전원 정책을 함께 검토해야 한다. WorkManager를 정확한 기상 타이머로 대신 쓰지 않는다.

시연 시간을 줄이려면 '데모 20초' 또는 가상 시계 이동 기능을 제공한다. 영상에 시간 단축 시연임을 표시하고 30분 동안 실제 대기한 것처럼 설명하지 않는다.

## 5. 상태 전이
~~~mermaid
stateDiagram-v2
    [*] --> Setup
    Setup --> Preparing: 시간·설정 확인
    Preparing --> Resting: 준비 완료 또는 타이머만 시작
    Preparing --> Setup: 취소
    Resting --> Ringing: 목표 시각
    Ringing --> Snoozed: 다시 알림
    Snoozed --> Ringing: 연장 시각
    Ringing --> RestorePending: 기상 확인
    Resting --> RestorePending: 중도 종료
    RestorePending --> Finished: 복구 확인 또는 건너뛰기
    Finished --> Setup
~~~
실제 차량이 움직이거나 상태가 불명확해지면 차량 제어 요청을 막고, 플랫폼 제한에 맞게 휴식 흐름을 중지/축소한다. UI가 백그라운드로 갔다고 시트 복귀를 실행하지 않는다.

## 6. 차량 제어 어댑터
우리가 정의하는 인터페이스:
- VehicleCapabilityProvider: 기능·권한·전원·차량 상태 확인.
- ClimateController: 현재 설정 조회, 요청, 응답.
- SeatController: 지원되는 자세 조회, 요청, 응답.
- AlarmOutput: 앱 소리/TTS 시작·중지.
- NapRepository: 세션·설정·기록 저장.
- Clock: 실제/테스트/시연용 시계.

공식 Vehicle SDK 소개에는 공조·좌석 관련 기능이 설명돼 있다. 실제 setter, 권한, 지원 차종과 좌석, 동작 가능한 전원 상태를 확인한 뒤 Pleos 어댑터를 구현한다. 사용자 제공 목록의 'Vehicle Control 준비 중'과 문서의 제어 소개가 일치하지 않을 수 있으므로, 권한이 있다고 추정하지 말고 SDK_VERIFICATION에 실제 결과를 기록한다.

### 제어 요청 상태
REQUESTED → ACKNOWLEDGED/FAILED/TIMED_OUT.
화면에서 버튼을 눌렀다는 이유만으로 '온도 설정 완료/시트 이동 완료'라고 표시하지 않는다. ACKNOWLEDGED도 요청 접수인지 물리적 적용 확인인지 어댑터 계약에 명시한다.

### 복구 규칙
- 시작 전에 읽은 유효한 원래 값만 저장한다.
- 앱이 변경한 항목만 복구 후보로 삼는다.
- 휴식 중 사용자가 수동으로 바꾼 항목은 덮어쓰지 않고 확인한다.
- 좌석 움직임은 사용자 확인·정차 조건·지원 여부를 충족해야 한다.
- 일부 항목만 성공하면 항목별 성공/실패를 보여준다. 공조 실패를 시트 성공으로 가리지 않는다.
- demoRelease에서는 실제 제어 구현을 호출하지 않는다.

## 7. 데이터 모델
| 모델 | 필드 예시 |
|---|---|
| NapSession | id, requestedDuration, startedAt, targetAt, status, endedAt, endReason |
| RestPreferences | preferredTemperature, seatPreset, alarmVolume, snoozeMinutes |
| OriginalVehicleState | sessionId, validFields, values, capturedAt, source |
| ControlAction | id, sessionId, target, requestedValue, state, resultSource |
| AlarmEvent | sessionId, sequence, scheduledAt, deliveredAt, acknowledgementAt |
| CapabilitySnapshot | supportedFields, permissions, powerState, checkedAt |

온도와 시트 값은 지원 범위에 맞게 검증한다. 실제 API가 없는 동안 숫자를 모의 값으로만 다룬다. 키 위치·문 잠금 해제·휴대폰 예약 이벤트는 '외부 입력이 들어왔을 때의 계획'과 실제 연동을 구분한다.

## 8. 화면·음성·알람
1. 시작: 남은 시간 선택, 기상 예정 시각.
2. 휴식 설정: 모의 온도·좌석, 적용 상태.
3. 휴식 중: 어두운 화면, 큰 남은 시간, 종료 버튼.
4. 알람: 기상 확인·다시 알림, 음성 명령.
5. 복구: 복구 항목 확인, 성공/실패, 건너뛰기.
6. 기록: 계획한 시간과 실제 앱 세션 시간.
7. 시연 패널: 20초 타이머·모의 예약·제어 실패·전원 상태.

알람은 갑자기 과도한 음량이 되지 않도록 앱의 허용 범위에서 조절하고 즉시 중지할 수 있게 한다. 호출·음성 안내와 오디오 포커스가 충돌한 상황을 테스트한다. 공조가 있다는 이유로 밀폐 공간의 내연기관 시동을 안전하다고 판단하지 않는다. 이 앱은 차량 내 체류 안전이나 기상을 보장하는 장치가 아니다.

## 9. Claude Code 작업 묶음
- N01: 시간 입력·Clock·순수 타이머 상태 모델.
- N02: 세션 영속 저장·프로세스 재시작 복원.
- N03: 실제 앱 소리/TTS·기상 확인·다시 알림.
- N04: Mock Climate/Seat 어댑터·성공/실패 피드백.
- N05: 원래 설정 저장·확인 후 복구.
- N06: 음성 명령과 모호한 시간 재확인.
- N07: release APK·20초 시연·한계 문서.
- N08(P1): 실제 지원되는 차량 상태/공조/좌석 연결.
- N09(후속): 휴대폰 예약·원격 준비·전원 OFF 알람 검증.

## 10. 필수 검증 사례
| ID | 상황 | 통과 조건 |
|---|---|---|
| N-T01 | 20초 실제 타이머 | 목표 시각 도달 시 알람 한 번, 단순 UI 새로고침으로 초기화 안 됨 |
| N-T02 | 5분 다시 알림 | 새로운 목표 시각 저장, 이전 알람 중지 |
| N-T03 | 시간 전 프로세스 종료·복원 | 남은 시간 복원, 시작부터 재계산하지 않음 |
| N-T04 | 시간 후 재실행 | 알람 지연/미실행 상태를 정직하게 표시 |
| N-T05 | 공조/시트 실패 | 타이머와 별개 상태, 성공으로 표시하지 않음 |
| N-T06 | 휴식 중 수동 설정 변경 | 자동 복구로 덮어쓰지 않고 확인 |
| N-T07 | 주행/UNKNOWN 입력 | 실제 제어 차단, 정책에 맞게 화면 제한 |
| N-T08 | 음성 시간 인식 모호함 | 확인 전 예약 확정 안 됨 |
| N-T09 | 종료 뒤 늦은 콜백 | 이미 끝난 세션 재알람·재제어 없음 |
| N-T10 | 모의 제어 빌드 | 실제 차량 제어 어댑터를 호출할 수 없음 |

## 11. 시연 영상 제안: 약 90초
기능·모의 범위 소개 10초 → 시간·온도·좌석 설정 20초 → 휴식 시작 및 20초 타이머 20초 → 실제 앱 소리·'일어났어' 15초 → 확인 후 모의 복구 15초 → 실제 연동 과제 10초.

음성 API를 아직 연결하지 못했다면 터치로 핵심 타이머를 완주하고 '음성 명령 연동 예정'으로 표시한다. 시트가 실제로 움직이지 않았는데 영상 편집으로 실차 제어처럼 보이게 하지 않는다.
